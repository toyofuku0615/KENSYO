# Gemini追加開発の検証結果（2026年10月29日・日本時間）

## 実装

- Google公式 `@google/genai` SDK 2.31.0。モデルの初期値は空で、実キーのモデル一覧から本人が選択します。別モデル・有料モデルへの自動切り替えはありません。
- `/settings/ai`：キーの暗号化保存・削除、モデル取得・選択、接続テスト、ON/OFF、利用量と上限の編集。
- 保存した本人のキーを優先し、未登録時のみ `GEMINI_API_KEY` を利用。キーの復号はサーバー・ワーカーだけです。保存済みキー全文はブラウザへ返しません。
- SQLite／Supabaseの追加ストレージとRLS。キー・キャッシュは本人のブラウザからも直接読めません。
- DBで日・月・分・月間トークンの予算を予約し、同時実行でも上限を確認。日・月はJSTで集計します。
- 同一解析のキャッシュ、429時の60秒〜最大15分の指数バックオフ、タイムアウト・出力不正時の手動確認。有料フォールバックやSDK内の自動再試行は行いません。
- 規約解析と汎用フォーム解析を既存の収集・応募ワーカーへ接続。Geminiの判定だけで未知・禁止規約を許可へ格上げしません。
- 型付きのプロフィール入力・公開根拠付き回答・ラジオ・選択・承認済み同意・次ページ・最終送信。最大6画面のループと時間上限があります。
- 入力値を持たないフォーム構造だけを解析し、入力中は通信を停止。送信直前に本人設定・キー設定・規約・情報源・URLを再確認します。
- DOM参照の差し替え、広告同意、経験の捏造、根拠が否定・矛盾するクイズ、既知PIIのURL/base64表記も拒否。
- 受付情報を確認できた場合だけ成功、結果不明時は自動再送なし。

開発中に見つかった型定義、キー／プロフィールのキャッシュ再検証、同意やDOM要素の変更、承認失効時の再確認、早すぎる通信、完了表示の誤認を修正してから上記を実行しました。接続確認と解析の件数が混ざらないよう、解析成功・失敗は規約／フォーム／回答のみを集計します。

E2EではGeminiの返答をモックし、実際のChromiumとローカルDBを使っています。基本・アンケート・自由記述・クイズ・複数ページ・順序変更で送信と受付番号保存を確認し、曖昧・回答不能・CAPTCHA・禁止の4種類は停止しました。キーの保存・マスク・削除、モバイル、既存応募の回帰テストも含みます。実在する懸賞へは送信していません。

## 未完了・制限

- 実際のGeminiモデル一覧・生成・接続確認は未実行です。APIキーがこの環境にありません。料金表もネットワーク制限で本文を取得できていないため、現在の無料対象モデルを確定したとは報告しません。
- 通信許可の `ai.google.dev` と `generativelanguage.googleapis.com` は環境設定の下書きへ追加済みですが、稼働中環境へは未適用です。ここで実接続するには、環境設定の確認・保存・環境のPublishが必要です。Vercelへのアプリ公開とは別の操作です。
- 利用量は本アプリのカウンターです。Google側の正確な残り枠や他アプリの使用を表さず、課金ゼロも保証しません。
- 任意の未知サイトが必ず操作できるわけではありません。曖昧なラベル、未知の必須項目、資格を照合できない条件、認証、購入、CAPTCHA、未承認通信先は手動確認へ移します。
- 実サイトの汎用送信は初期状態でOFFです。明示したホスト、関連規約、本人の自動応募・個人情報利用同意等の条件が必要です。今回、これらを実サイト向けに有効化していません。
- 本番Supabaseへの追加SQL適用やVercelデプロイは未実行です。
