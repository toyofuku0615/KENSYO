# 実装範囲と運用上の制限

## 現在動く範囲

- ローカル SQLite、暗号化プロフィール、設定、キャンペーン・応募・当選履歴。
- Supabase 用の Auth 接続、所有者で分離する RLS、サービス用 DB アダプター、マイグレーション。
- RSS と HTML の収集、公式ページリンク追跡、URL ベースの重複排除、期限切れ除外。
- 規約・サイト規約のルールベース分類と根拠保存、資格・同意・カテゴリの検証。
- ローカル検証フォームへの Playwright 入力、確認画面、最終送信、受付番号確認。
- DB 予約による二重応募防止、日次上限、結果不明時の再送停止、緊急停止。
- ワーカー分離、6 時間ごとの GitHub Actions、Web からの実行予約。

テストデータは UI に明示し、実績として作り込んだ架空の件数を表示しません。デモ応募の数は検証用 DB 内の記録です。賞品は届きません。

## 実サイトへの自動送信

同梱する送信アダプターは `local-test` のみです。収集した実在サイトを、未知のフォームのまま自動で送信する機能は有効にしていません。型付けされた汎用入力計画は実装していますが、不明な必須項目・未承認の同意・認証・広告登録は手動確認に移します。

対応を追加する際は、応募規約だけでなくサイト全体・プラットフォームの規約、応募回数、送信先、完了画面、同意、ブラウザ通信先を確認した専用アダプターが必要です。`silent` は許可証ではありません。規約が古い・矛盾する・取得できない場合は送信できません。

CAPTCHA、Bot 検知、ログイン、SNS 操作、メール確認、購入、本人未承認の契約には対応しません。制限回避、指紋偽装、プロキシローテーション、CAPTCHA 代行は実装しません。

## 収集と規約解析

取得先は利用条件の確認と完全一致のホスト許可が必要です。robots.txt が取得できない場合も収集を止めます。収集対象サイトは初期版に実在の有効ソースとして登録されていません。サイトごとの許諾を確認してから追加してください。

ページ表現の違い、JavaScript 描画、曖昧な締切、画像内の規約、別ドメインの応募画面などで抽出できない場合があります。年が不明な締切を推測しません。同じ公式 URL を共有する別企画は URL ベースの重複排除で統合される可能性があり、専用アダプターで識別を拡張する必要があります。

規約分類はルールベースで、自然言語の全条件を完全に解釈するものではありません。AI API の接続は初期版には含めていません。未設定でもすべてのローカル検証が動作します。将来 AI を追加する場合も、外部 HTML を命令として実行させず、型検証した抽出結果に限って利用し、送信可否は独立したルールで決めます。

SSRF 対策では公開 IP、HTTPS、許可ホスト、リダイレクト先を確認します。クラウドプロキシ経由ではプロキシ側で名前解決されるため、プロキシの送信先制限も必要です。環境側のネットワーク許可リストをサイト追加時に更新してください。アクセス制限を回避する代替経路は使いません。

`HTTPS_PROXY` / `https_proxy` がある環境では、その信頼するプロキシが名前解決後の private / reserved 宛先を常に拒否することを運用者が確認できた場合だけ `KENSHO_PROXY_PUBLIC_DESTINATIONS_ONLY=1` を設定します。未確認ではリモート収集を停止します。アプリ側の DNS 検証だけではプロキシ側の別の DNS 解決を固定できません。通常のプロキシを使わない GitHub Actions とローカル fixture にこのフラグは不要です。

## クラウドと費用

Supabase / Vercel / GitHub の接続情報がない環境では、実アカウントへの公開やスケジュール実行の成功を確認できません。ローカルの検証結果と、実クラウドに配置した状態の検証は区別してください。

無料枠を利用できますが、保存量、メール、帯域、Actions の実行時間、プロジェクト休止などの上限があります。月額 0 円や永久稼働を保証する構成ではありません。GitHub Actions の定期実行は遅延・停止する場合があります。画面からの予約は次のワーカー実行まで待ちます。

Vercel 上でローカル SQLite を永続 DB として使うことはできません。クラウド公開は `supabase` モードを使用してください。初期実装は小規模運用を対象としており、ユーザー・キャンペーン件数が増える場合はページネーション、保持期間、処理量とタイムアウトの設計を拡張してください。

## 当選と Gmail

当選・落選は本人が手動で登録します。入力する獲得額は実際に確認した賞品の推定額です。応募総数が不明なため、真の当選確率は算出しません。

Gmail OAuth、メール検索、当選メール照合は未実装です。将来は応募履歴と通知を関連付ける拡張ができますが、この初期版はメールを読み取り・保存・削除・送信・転送しません。

## 個人情報と監査

暗号化は DB 上のプロフィールを保護しますが、認証した本人の編集画面と送信ワーカーでは必要な範囲で復号します。暗号鍵と DB を同時に取得される侵害からは保護できません。運用者は service role key と暗号鍵の管理責任を持ちます。

送信後のキャンセル・外部サイトへ渡した情報の削除は外部サイトで手続きが必要です。緊急停止は既に完了した送信を取り消しません。応募結果が不明なものを本人が手動で解決した場合も、再送による二重応募に注意してください。
